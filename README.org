#+title: My .files

This repository contains my personal configuration files (dotfiles) for various applications and tools.

** What is a Dotfile?
Dotfiles are configuration files for Unix-based systems that start with a dot (.), such as:

~/.gitconfig

These files store user preferences and settings for different command-line tools, text editors, and system behaviors.

** Installation
To set up these dotfiles on a new system, clone the repository and run
the install script:

#+begin_src sh
git clone https://github.com/unipro/dotfiles.git ~/dotfiles
cd ~/dotfiles
./install.sh
#+end_src

=install.sh= *copies* the managed files into =$HOME=, =~/.config= and
=~/.claude= (it does not create symlinks). Any existing target is moved
aside to =<file>.backup= first, and a pre-existing =.backup= is never
overwritten — so your original files stay safe and re-running is idempotent.

The =claude= component is the one exception: it syncs *both ways* rather
than only repo → home. See [[#claude-code][Claude Code]] below.

*** Installing a subset
With no arguments =install.sh= installs everything. To replace only part
of the configuration, name the components you want:

#+begin_src sh
./install.sh --list       # show the available components
./install.sh doom         # only ~/.config/doom
./install.sh bash git     # only the shell and Git configs
./install.sh all          # explicit alias for "everything"
#+end_src

| Component      | Installs                                                                    |
|----------------+-----------------------------------------------------------------------------|
| =bash=         | =~/.bashrc=, =~/.bash_profile=, =~/.profile=, =~/.config/bash/= + =mkenv=, and the generated shell env |
| =git=          | =~/.gitconfig=, with =~/.gitconfig.local= inlined                           |
| =clang-format= | =~/.clang-format=                                                           |
| =doom=         | =~/.config/doom/=                                                           |
| =ghostty=      | =~/.config/ghostty/=                                                        |
| =claude=       | =~/.claude/CLAUDE.md= (two-way sync, newest side wins)                       |

Unknown component names are rejected before anything is copied, and the
components always run in the order listed above regardless of argument
order.

** Managing Updates
Pull the latest changes and re-run the install script to propagate
them (since files are copied, not symlinked, a =git pull= alone does
not update the installed copies):

#+begin_src sh
cd ~/dotfiles
git pull origin main
./install.sh
#+end_src

If you only changed one area, re-install just that component — e.g.
=./install.sh doom= after editing =dotconfig/doom/config.el=.

To contribute your own changes back, edit the files in the repository,
then commit and push:

#+begin_src sh
git add .
git commit -m "Update configurations"
git push origin main
#+end_src

** Local Git Configuration
To set system-specific Git configurations, you can use `~/.gitconfig.local`. This file is not included in the repository and should be created separately for each system.

Example content of `~/.gitconfig.local`:

#+begin_src ini
[user]
    name = Byungwan Jun
    email = unipro.kr@gmail.com

[credential]
    helper = osxkeychain
#+end_src

** Shell Configuration
The bash configuration is split into two layers, both cross-platform
(macOS and Linux):

*** Login entry points (installed to =$HOME=)
These are the standard bash startup files, kept as a single
cross-platform version each and copied into =$HOME= by =install.sh=
(an existing file is moved aside to =<file>.backup= first):

- =.bash_profile= : login shells; bootstraps Homebrew, then sources
  =~/.profile= and =~/.bashrc=
- =.profile=      : POSIX login setup (private =bin= PATH, cargo env)
- =.bashrc=       : interactive shells; history, prompt, =ls= colors,
  then sources =~/.config/bash/init=

OS differences (Homebrew vs Linuxbrew, =ls -G= vs =ls --color=auto=,
=/etc/bashrc= vs =/etc/bash.bashrc=) are handled inline via =$OSTYPE=,
so the same files work on both platforms.

*** Reusable scripts (installed to =~/.config/bash/=)
=install.sh= installs the following into =~/.config/bash/=:

- =init=       : entry point sourced from =~/.bashrc=; loads the rest
- =aliases=    : interactive aliases and helper functions
- =completion= : user bash-completion loader
- =mkenv=      : generates the machine-specific env files

The config files (=init=, =aliases=, =completion=) live in
=dotconfig/bash/= as part of the XDG config tree. The =mkenv= generator
lives at the repository root (it builds files rather than being one).

Run =mkenv= to (re)generate environment files for the current machine
(=install.sh= runs it automatically):

#+begin_src sh
~/.config/bash/mkenv
#+end_src

This writes =~/.config/bash/env= (bash) and =~/.config/zsh/env= (zsh).
Both =env= and a private =~/.config/bash/private= (for machine-local
secrets/aliases) are git-ignored and never committed.

** Doom Emacs
The [[https://github.com/doomemacs/doomemacs][Doom Emacs]] configuration lives in =dotconfig/doom/= and is
installed to =~/.config/doom/= by =install.sh=.

- =init.el=     : enabled Doom modules
- =config.el=   : personal configuration
- =packages.el= : extra packages
- =bin/=        : helper scripts

Machine-local overrides go in =~/.config/doom/local.el= (and
=custom.el=); both are git-ignored and never committed. After changing
=init.el= or =packages.el=, run =doom sync=.

** Claude Code
:PROPERTIES:
:CUSTOM_ID: claude-code
:END:
[[https://claude.com/claude-code][Claude Code]] keeps its user-level configuration in =~/.claude= rather
than the XDG tree, so it gets its own source directory =dotclaude/=
instead of living under =dotconfig/=:

- =CLAUDE.md= : global instructions loaded into every session on this
  machine

Everything else in =~/.claude= is runtime state that Claude Code
generates and owns (=sessions/=, =projects/=, =history.jsonl=, caches,
=settings.json=). =install.sh= only looks at the files present in
=dotclaude/=, so that state is never read, written, or pulled into the
repository. To manage another file, add it to =dotclaude/= and it is
picked up automatically.

*** Two-way sync
The global rules get edited from inside a Claude Code session about as
often as they get edited in the repository, so =./install.sh claude=
syncs rather than overwrites — for each file in =dotclaude/=:

1. contents identical → nothing happens
2. =~/.claude= copy is newer → it is copied *into the repository*
3. =dotclaude/= copy is newer → it is installed to =~/.claude= (with the
   usual =<file>.backup=)

#+begin_src sh
./install.sh claude       # reconcile both sides, newest wins
git diff dotclaude/       # review whatever got pulled in
#+end_src

One caveat: Git restamps the files it checks out, so a file touched by
=git pull= looks newer than an older local edit and wins. Run
=./install.sh claude= *before* pulling to capture local edits first.
